# 接入行为（0.3.2）

主要场景为 SnowLuma + qq-bridge + DSH Web。安装在桥接实际连接的 web profile 中，核对该实例的端口和 DSH_HOME。

## 默认选择

调用 bfy_ofm_onboard 或 /bfy-ofm onboard 时，未指定来源就先选择可确认的直接 DeepSeek 免费池；显式指定 qoder、qodercn、trae 等时选择该账号渠道。支持 trea 拼写别名。保持原思考档位；无法保持时说明原因并保留原选择。

这次显式操作通过宿主选模接口应用到当前会话，并由宿主保存为默认值。安装、创建或恢复聊天本身不会触发本插件改选。用户手动选模和 qq-bridge 的选模始终正常生效；不限制其他 OFM 模型、聚合模型、自定义模型或官方模型。

OFM 侧共有三条接入车道，按"先跑通、再求稳"引导：① 免费公开池（Kilo 免密，onboard 默认）；② EAC 协付池（在 OFM 设置页完成 GitHub 授权——登录并 star 上游仓库——后解锁，仅桌面端宿主可见，Web 与 CLI 没有）；③ 十个本人账号渠道（qoder、qodercn、trae、zcode、gemini、cline、loomy、raccoon、lobsterai、minimax，onboard 后接渠道名）。各车道的接入方式、可用模型与局限见 [池子与账号](public-pool-and-accounts.md)。EAC 模型无需本插件接入：授权后就是目录里的普通条目，手动或桥接直接选即可。

## OFM 安装

本插件不安装、不挂载、也不携带 OFM 副本。0.3.1 曾把官方 scoped OFM 作为依赖并从 bundle patch 里再插入一行，那一行按裸包名挂载，会连带把 OFM 的浏览器半身再注册一次；其结果是同一次安装的效果取决于装载顺序，最坏情况是桌面端启动审计直接终止（见 docs/crash-investigation-0.3.1.md）。0.3.2 起改为按能力检测：宿主提供了 OFM 的账号池服务，或已注册 our-free-model / our-free-model-region 路由，才认为 OFM 可用；否则 onboard 与 status 直接返回 OFM_NOT_MOUNTED 及安装入口，不去探测宿主接口，也不会替你写 profile 配置。

安装 OFM 请使用宿主的插件管理器（桌面端应用内插件管理器，Web profile 用 dsh plugin 按其官方仓库 https://github.com/Ebony-Vinyl/dsh-our-free-model 的当前说明装载），并确认它处于启用状态。接入时若发现 OFM 总开关是关闭的，本插件会把它改为启用以完成你明确要求的接入，并在结果里用 ofmEnabledByThisRun 与说明回执这一次全局改动；不改隐藏模型、凭据、账号排序、限流锁或其他网关设置。账号登录、积分领取及权益核对由本人完成。

## 默认不自动转到官方

免费池失败时返回原因与下一步，不自动用官方余额兜底。用户可以自行在 DSH 中切换模型；插件另提供 fallback --confirm-official-billing 便捷命令，其近期故障与确认条件只适用于这个命令，不限制宿主的手动选模。便捷命令只更改当前会话，不重放结果未知的旧任务。

## 只观察调用

llm/stream 中间件只观察已发生的路由及完成状态，不拒绝、替换或重放请求。0.3.2 起观察记录改为内存态加异步合并落盘：每次模型调用不再同步读写策略文件，避免同步磁盘 I/O 进入所有会话的公共链路（OneDrive、网络盘或杀软占用时那会卡住整个进程）；写入失败只告警，临时文件不残留。记录读取、写入失败时继续正常模型调用。已确认接入路由按会话保存用于比较证据，不是允许列表。

## 宿主调用的时限与取消

宿主接口本身不带超时，且内核的工具超时策略只在工具主动配合取消时才生效。因此本插件对每一次宿主往返（目录读取、选模、账号池预检、OFM 设置接口）都设了默认 15 秒的本地上限，并透传命令与工具调用的取消信号：超时报 HOST_CALL_STALLED、取消报 HOST_CALL_CANCELLED，回合立即得到可读的结果，而不是等一个永不返回的调用把会话挂死。上限可用 hostTimeoutMs 调整；被中断的调用结果未知，插件一律不当作已完成。

账号备用检查使用 OFM 原有 getAvailableAccount 排除首账号后检查备用；实际模型调用中记录不同选号的数量及切换布尔值，不保存账号标识或凭据，不改变 OFM 的选号结果。预检不算实际切换。

公开池没有账号，账号轮换不适用。两个可用账号只证明有备用，真实额度故障切换需另有实际回执。宿主提交可能对应多次上游恢复，物理请求数和实际扣费不从回执推断。

## 升级

0.3.1 移除 0.3.0 的全局模型封锁与 agent/created 自动改选。旧 onboarding-policy.json 保留作接入和回执记录，不再控制模型权限；不可读时接入命令报告问题，普通模型调用继续。旧 config.local.json 保留。桌面端曾手工停用插件条目时，升级后通过应用插件管理器重新启用。

从 0.3.1 升到 0.3.2：本插件不再自带 OFM，所以升级后请先确认 OFM 作为一个独立 bundle 处于启用状态（插件管理器里应能看到它），再运行 /bfy-ofm onboard。若 0.3.1 的安装曾因网络失败而残留空的 node_modules/@ebony-vinyl 目录，可以在宿主插件管理器重新解析依赖后清掉；不影响本插件装载。0.3.2 另在 package.json 声明了 engines.dsh，宿主兼容性门会拒绝过旧的运行时并给出可确认放行的提示，不再让插件在调不到的接口上半路失败。
